# REVIEW.md

## Starter Code Review (`app/main.py`)

Below is the structured review of defects identified in the starter code provided by HROne, detailing the location, defect explanation, how it was observed/reproduced, and the corrective action applied.

| # | Where (function / line) | What is wrong | How you'd notice it (test, input, or symptom) | How you fixed it |
|---|---|---|---|---|
| 1 | `health` (lines 72–74) | Returns `{"status": "ok"}` unconditionally without checking MongoDB connectivity or pinging the server. | Test with MongoDB stopped: endpoint still returns `200 OK` instead of expected `503 Service Unavailable`. | Implemented `client.admin.command("ping")` inside a try-except block, raising `HTTPException(503)` on failure. |
| 2 | `compute_late_minutes` (lines 33–38) | Directly replaced hour/minute on `punch_in` without timezone conversion; if `punch_in` is UTC, replacing hours produces corrupted mixed-zone time. Also `minutes > 10` failed for boundary punch-ins: punch-in at 09:40:01 with 09:30 shift is 10 min late (R2), but `(punch_in - start) / 60` truncated to 10 and was discarded by `> 10`. | Punch-in at 09:40:01 IST returned `late_minutes = 0` instead of `10`. | Converted `punch_in` to IST, constructed `shift_start` on the attendance date in IST, verified `elapsed_sec > 600`, and calculated `int(elapsed_sec // 60)` elapsed minutes from `shift_start`. |
| 3 | `compute_work_hours` (lines 40–42) | Used Python's built-in `round()`, which performs round-half-to-even (banker's rounding), violating business rule R4 & R8 requiring round half-up. | `compute_work_hours` with diff yielding `.005` rounds down to `.00` on even integers instead of up to `.01`. | Replaced with `Decimal.quantize(Decimal("0.01"), rounding=ROUND_HALF_UP)`. |
| 4 | `compute_overtime` (lines 44–48) | Ignored the 30-minute threshold requirement in R3 ("counted only if >= 30; otherwise 0"). Credited overtime for 5 or 10 minutes past shift. Also did not advance shift_end across midnight for overnight shifts. | Punch-out at 18:35 for 18:30 shift returned `overtime_minutes = 5` instead of `0`. | Implemented check `minutes if minutes >= 30 else 0`, and added overnight shift calendar date advancement for `shift_end`. |
| 5 | `create_employee` (lines 77–86) | Check-then-insert race condition (`if find_one`); missing DB unique index allowed concurrent duplicate creates. Missing validation on `emp_code` regex (`^EMP\d{4,6}$`), shift format, and `shift_start != shift_end`. Stored naive `datetime.now()` and returned datetime instead of epoch ms. | Concurrent requests create duplicate employees; invalid codes like `"EMP"` accepted; `created_at` returned as ISO string instead of epoch ms. | Created unique index on `emp_code` at startup, caught `DuplicateKeyError` -> 409, added Pydantic validators, and serialized `created_at` to integer epoch milliseconds. |
| 6 | `list_employees` (lines 88–96) | Off-by-one pagination bug: `skip = page * page_size` skips page 1 completely (skips first 20 records on `page=1`). Missing sort by `emp_code` ascending. Total counted entire collection rather than filtered set. | Querying `/employees?page=1` returned items starting from index 20; `total` did not change when filtering by `department`. | Changed skip formula to `(page - 1) * page_size`, added `.sort("emp_code", ASCENDING)`, and used `count_documents(q)` on filtered query. |
| 7 | `punch_in` (lines 99–121) | Check-then-insert race condition allowed duplicate punches for same day under concurrency. Missing 404 check if employee does not exist (`emp["shift_start"]` caused 500 error). Failed to handle R1 overnight shift date assignment. Exposed internal MongoDB `id` (`doc["id"] = str(res.inserted_id)`). Stored and returned naive datetime instead of epoch ms. | Concurrent duplicate punch-ins both returned 201; nonexistent employee returned 500 instead of 404; internal MongoDB `id` appeared in response body. | Created unique index on `(emp_code, date)`, caught `DuplicateKeyError` -> 409, validated employee existence -> 404, implemented R1 overnight date resolution, omitted `_id`/`id`, and formatted timestamps as epoch milliseconds. |
| 8 | `list_attendance` (lines 124–150) | Loaded entire collection into memory with `list(db.attendance_logs.find(q))` and sorted in Python (`docs.sort(...)`), causing severe latency and memory exhaustion on large datasets (~100k docs). Exposed internal `id`. Missing date range validation (`date_from > date_to`). Returned datetimes instead of epoch ms. | High memory consumption; querying with `date_from > date_to` returned 200 with empty list instead of 422; `id` exposed in output. | Pushed sorting and pagination down to MongoDB with `.sort([("date", DESCENDING), ("emp_code", ASCENDING)]).skip(skip).limit(page_size)`, added 422 validation, and serialized all timestamps to epoch ms. |
| 9 | Timezone Naive/Aware Conflict | PyMongo returns naive UTC datetimes by default; subtracting with aware `datetime.now(tz=timezone.utc)` raised `TypeError: can't subtract offset-naive and offset-aware datetimes`. | Calling `punch_out` on previously stored record threw unhandled 500 `TypeError`. | Implemented `ensure_utc()` utility to guarantee consistent UTC timezone awareness across all datetime calculations and comparisons. |
| 10 | Missing Contract Endpoints | Six required endpoints were completely missing: `punch-out`, `regularize`, `employee_monthly`, `department_summary`, `late_leaderboard`, `department_trend`, and `admin/explain`. | Automated contract validation against OpenAPI specification failed with 404 on all analytics and management endpoints. | Implemented all remaining endpoints according to `openapi.yaml` and `DATA_MODEL.md` requirements. |

## Non-Defects Examined and Retained

1. **Calendar Dates and Times Stored as Plain Strings**:
   - `date` (`"YYYY-MM-DD"`) and shift times (`"HH:MM"`) are strings in MongoDB.
   - *Reason*: This is explicitly specified in `DATA_MODEL.md` (lines 22–25) to avoid arbitrary timezone shifts on calendar dates and recurring daily shift times.
2. **Initial Derived Values at Punch-In**:
   - Storing `work_hours: null`, `overtime_minutes: 0`, `half_day: False`, and `history: []` upon punch-in.
   - *Reason*: Authoritative per `DATA_MODEL.md` (section 3); derived work duration values only apply once a punch-out or regularization occurs.
